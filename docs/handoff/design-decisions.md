# 設計判断ログ

## この文書の役割

WHATNOT出荷アプリ開発プロジェクトで行われた重要な設計判断の記録。各判断の「**何を決めたか**」「**なぜそう決めたか**」「**どの代案を却下したか**」「**どの条件で再検討すべきか**」を残す。

新しい対話セッションを開いた設計役が、過去に検討して却下された案を再提案しないため、また、設計の背景を理解した上で改善提案を行うために参照する。

## 参照方針

- 新たな設計提案を行う前に、関連する DD（Design Decision）を確認すること
- 「却下した代案」と同じ提案をする場合は、再オープン条件に該当する根拠を示すこと
- DD の内容と CLAUDE.md / design_role.md が矛盾する場合、現行の正文（CLAUDE.md / design_role.md）を優先する
- 本ログへの追記は新たな重要判断が発生した時に行う。岡本さん承認制

## 凡例

- 状態：採用中／一部修正済み／撤回済み
- 関連 DD：他の DD との依存関係
- 詳細経緯が必要な場合：移行作業の議論履歴（移動済みセッション）を参照

## DD-002（2026-05-25）：CLAUDE.md と architect.md を分離

**状態**：撤回済み（2026-06-01）

**判断**（撤回前の原文）：

**撤回理由（2026-06-01 CoWork 開発体制再定義セッション）**：
- 2026-05-27 リーダーセッションで Cowork サブエージェント仕様の公式確認結果（自動委任モデルのみ・サブエージェント間 spawn 不可・background 時 prompt auto-deny）により Phase B 設計前提が崩壊した

- `.claude/agents/` 配下に置く必然性が消失したため、`knowledge/design_role.md` への移動・改訂を実施
- 2 ファイル分離自体（CLAUDE.md と 設計役挙動定義の分離）は引き続き有効。`.claude/agents/` への配置のみを撤回
- 後継：**DD-008**（CoWork 設計役一本化・サブエージェント不採用）

**背景**（撤回前の原文）：

- architect.md は Phase B でサブエージェント化する前提配置（`.claude/agents/<name>.md` 規約）

**却下した代案**（撤回前の原文）：

**再オープン条件**：
- 撤回済みのため、再オープンは新たな DD として起票する

## DD-003（2026-05-25）：architect.md 自動ロードに対応A 強化版を採用

**状態**：採用中（強化版）

**補正注記（2026-06-01 DD-008 採用に伴う）**：

**判断**：
CLAUDE.md は Cowork により自動ロードされるが、architect.md は自動ロードされない。これを補うため、CLAUDE.md 冒頭に「対話開始時に architect.md を必ず読み込む」旨を**強い指示文**で記載する。

強化版文言の要点：
- 「【対話開始時の必須動作 ─ 確認不要・自動実行】」
- 「最初のユーザー入力に応答する前に、Read ツールを使って必ず読み込む」

**背景**：
- テスト A の初期検証で、CLAUDE.md は自動ロードされたが architect.md は読まれなかった

**却下した代案**：

**再オープン条件**：
- 強化版でも architect.md が読まれない事例が頻発した場合
- Cowork の仕様変更で自動ロード機構が変わった場合

## DD-005（2026-05-25）：Phase A 自動化は「明示宣言型トリガー」を採用

**状態**：採用中

**判断**：
残論点ファイルの自動更新は、architect が `[残論点更新] ID:XXX / 状態:旧 → 新` のような**明示宣言**を出した時にトリガーされる。会話内容の自動スキャンや状態の自動分類は行わない。

宣言構文：
- 新規追加：`[残論点追加]`
- 状態変更：`[残論点更新]`
- カテゴリ変更：`[残論点移動]`
- クローズ：`[残論点クローズ]`
- アーカイブ移動：`[残論点アーカイブ移動]`

宣言を受けて、Cowork（または Edit ツール経由で architect）がカテゴリファイル＋索引版を**同一トランザクション**で更新し、整合チェックを実行する。

**背景**：
- architect の判断主体性を維持する必要がある
- 自動分類は判断ミス（誤分類）のリスクが高い
- 設計役の自己点検ルール（仮説／確認候補／未確認の明示）と矛盾しない設計が必要

**却下した代案**：
- 会話末尾スキャン型（チャット終了時に自動で論点を抽出する）→ 自動分類のリスク
- 実装連動型（Claude Code 完了報告から自動でクローズ）→ 確認プロセスの飛び越し
- 完全手動（自動化なし）→ Cowork 移行の意義が薄れる

**再オープン条件**：
- 宣言式の運用が煩雑だと判明した場合（テスト C ではシナリオ A 達成、現時点では問題なし）
- 自動分類の精度が許容範囲に達した場合（将来的な AI 性能向上時）

**関連 DD**：DD-004, DD-006

## DD-006（2026-05-25）：「完了 + 後続参照なし → アーカイブ移動」二段階運用を採用

**状態**：採用中

**判断**：
論点が「完了」になっても自動でアーカイブ移動しない。二段階で扱う：
- **段階1：完了** → カテゴリファイル内に維持（他論点との参照関係がある場合は明記）
- **段階2：アーカイブ移動** → 「後続参照なし」が確認された時に `完了アーカイブ.md` へ移動

**背景**：
- 既存運用がこの二段階を採用している（完了アーカイブには 2 件のみ、完了状態の論点は多数）
- 完了アーカイブの header に「対象：完了済み・後続参照なし・アーカイブ確定論点」と明示されている
- 後続 Step や別論点で参照される可能性がある完了論点は、カテゴリファイルに残す必要がある

**却下した代案**：
- 完了即アーカイブ移動（クローズ = アーカイブ）→ 既存運用と矛盾、参照関係の保持が困難
- アーカイブ移動という概念自体を廃止 → 完了論点が肥大化して見通しが悪くなる

**再オープン条件**：
- アーカイブ概念の運用負荷が高すぎると判明した場合
- 別の参照関係管理機構が導入された場合

**関連 DD**：DD-005

## DD-008（2026-06-01）：CoWork 設計役一本化・サブエージェント不採用

**状態**：採用中

**判断**：
CoWork 側を「出荷アプリ設計役」として一本化する。CoWork 内のサブエージェント化（旧 Phase B 構想）を採用しない。

具体的には：
- 設計役の挙動定義は `knowledge/design_role.md` に集約する（旧 `.claude/agents/architect.md` から移動・改訂）
- `.claude/agents/` 配下には現役 MD を置かない（空運用）
- 監査役は CoWork 内には取り込まず、外部監査として運用する。当面は ChatGPT 監査チャットを継続利用し、将来的に Claude Chat 側の出荷アプリ監査役プロジェクトへ移行する余地を残す。岡本さんがコピペハブとして CoWork（設計役）と監査役の間を介在する（CLAUDE.md 2.3 ／ design_role.md 4.2 と同趣旨）
- Phase A／B 区分そのものを撤回。ファイル更新自動化（明示宣言型）のみ旧 Phase A の中核機構として継続採用
- IMP-08（エージェントMD 編集の正規ルート整理 + 安全手順策定）を全廃棄。`knowledge/agent_md_editing_safety.md` を新設しない
- 関連退避：`.claude/agents/auditor.md`・`knowledge/audit_log.md`・`knowledge/phase_b_design.md`・`knowledge/test-operations-guide.md`・`.agent-drafts/agent_md_editing_safety.draft.20260527-01.md` を `knowledge/archive/` へ退避

**背景**：
- 2026-05-27 リーダーセッションで Cowork サブエージェント仕様の公式確認結果（Claude Cowork サポートページ・Claude Code subagents ドキュメント）が以下と判明：
  - Cowork は Claude による自動委任モデルのみ
  - サブエージェントは他サブエージェントを spawn 不可
  - background 時は対話プロンプト auto-deny
  - `@` メンション切替・`--agent` フラグ・`/agents` 管理コマンドは CLI Claude Code 専用機能（Cowork 内では使えない）
- これにより Phase B 設計の前提（architect・auditor をサブエージェントとして `.claude/agents/` 配下に配置し、`@` メンションで切替える運用）が成立しないと認定された
- 2026-05-27 リーダーセッションでは Phase B 再設計のブレストが第一フェーズまで進行したが、2026-06-01「CoWork 開発体制再定義セッション」で岡本さんが**方向 A（CoWork 設計役一本化）**を採用判断
- IMP-08 残処理（β・γ・新ファイル本体反映・E・(5)）は方向 A 採用により全廃棄
- 監査役の独立性は、岡本さんがコピペハブとして物理的に分離されたチャネル（ChatGPT）に渡すことで担保される（過去の運用と同じ構造）

**却下した代案（CoWork 開発体制再定義セッションで検討）**：
- **方向 B：CoWork サブエージェント化を続行（命名・起動論理を再設計して継続）** → Cowork 公式仕様の制約（自動委任のみ・spawn 不可・auto-deny）を回避できる根拠が示せず、再設計コストが Phase B 設計時を上回ると判断
- **方向 C：CoWork 外（CLI Claude Code 等）でサブエージェント体制を構築** → 岡本さんのコピペハブ運用との整合性が崩れ、運用負荷増。Cowork 移行の目的（引継ぎ負荷削減）に逆行
- **IMP-08 だけ継続して残処理を完遂する案** → サブエージェント不採用が確定した時点で `.claude/agents/` 配下に MD を置く必要性が消失。残処理の前提が崩壊しており継続する意味がない

**再オープン条件**：
- Cowork のサブエージェント仕様が大幅に変更され、自動委任以外の起動モデル・spawn 可能化・background 制約解除のいずれかが実現した場合
- 岡本さんが「設計役と監査役の両方を Cowork 内で完結させる」運用に切り替える明確な判断をした場合（その際は新規 DD として起票）

**関連 DD**：DD-002（撤回済み・本 DD の前段階）、DD-003（自動ロード対応A 強化版・本 DD 採用後も維持）
